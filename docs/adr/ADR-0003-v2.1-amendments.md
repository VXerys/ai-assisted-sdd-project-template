# ADR-0003: v2.1 amendments

Amends parts of ADR-0002 (Packaging, Hookless parity, Context size, and the slash commands of Lifecycle); every other ADR-0002 decision stands. Evidence: `docs/research/2026-10-22-sdd-landscape-benchmark.md` in the template repository.

## Context

A benchmark on 2026-10-22 against spec-kit, OpenSpec, BMAD, Kiro, cc-sdd, copier/cruft, and the official Claude Code, npm, and GitHub docs found four facts that ADR-0002 did not account for:

- npm 12 sets `allow-git` to `none` by default, so `"@vxerys/sdd": "github:VXerys/sdd#v2.1.0"` no longer installs without an opt-in (https://docs.npmjs.com/cli/v12/commands/npm-install).
- Claude Code cloud sessions with one repository run the repository's `.claude/settings.json` hooks; sessions with several repositories and project threads do not, and cloud sessions never install plugins a repository enables (https://code.claude.com/docs/en/cloud-environments).
- Claude Code, Codex, Cursor, Copilot, and Kiro read `AGENTS.md` natively; Copilot and Kiro load their own files alongside it, so an adapter that copies `AGENTS.md` loads twice. Claude Code `.claude/rules/*.md` with `paths:` load only when a matching file is read or edited (https://code.claude.com/docs/en/memory, https://agents.md/).
- `.claude/commands/` files keep working and accept the skills frontmatter except `name` and `paths`, including `disable-model-invocation` (https://code.claude.com/docs/en/skills).

## Decision drivers

1. A derived project must get template fixes without hand-copying, and without overwriting files its owner edited.
2. No outward action (new repository, npm account, publish) before the owner takes it.
3. Every rule loads once per tool; always-loaded context stays small.
4. The gate works where hooks do not run.

## Decision

**Distribution.** The tooling stays in this repository until extraction to `@vxerys/sdd` is worth a second repository. A CLI, `scripts/sdd/cli.mjs` (`npm run sdd -- <command>`, `bin: sdd`), is the single entry point: `brief`, `guard --check`, `validate`, `render`, `sync`, `status`, `check`, `upgrade`. When the package is extracted, it is published to npm with trusted publishing (OIDC, provenance); until then a GitHub-tag dependency needs `allow-git=root` in the project's `.npmrc`. The release workflow carries a publish job that runs only when the repository variable `NPM_PUBLISH` is `true`.

**Upgrade.** Copier's model with spec-kit's ownership check:
- `init` records `template: { version, commit, answers }` in `sdd.config.json` and writes `.sdd/manifest.json` with the SHA-256 of every managed file it produced.
- `sdd upgrade --from <template checkout> [--to <ref>] [--dry-run] [--conflict inline|rej]` refuses a dirty tree, rebuilds the old base by running the recorded template commit's `init` with the recorded answers in a temp directory, renders the new version the same way, and for each managed file: unchanged since the manifest → take the new file; edited → `git merge-file` 3-way merge; conflicts → inline markers or a `.rej` file. Removed managed files are deleted only when unedited. Then it runs version-keyed migrations, rewrites the manifest and `template.version`, renders, syncs, and validates.
- Managed paths default to the tooling, templates, commands, settings, CI, and protocol documents, overridable in `sdd.config.json` `managed`; steering, specs, product, ADRs, handoff, and assumptions are never managed.
- `sdd status` lists edited managed files; `sdd check --from <checkout>` exits 1 when the project is behind.

**Hook scope.** Repository hooks are the primary gate locally and in single-repository cloud sessions. `sdd brief`, `sdd guard --check`, and `sdd validate` are required only in multi-repository cloud sessions, project threads, and tools without hooks; routine prompts call them. `guard --check` fails on secrets and frozen paths in the diff and reports protected paths (`--strict` fails on them). In cloud sessions (`CLAUDE_CODE_REMOTE=true`) SessionStart runs `npm ci` when `node_modules` is missing. A Claude Code plugin is not a distribution channel.

**Adapter dedupe.** `AGENTS.md` carries identity, read-first, read-only paths, `rules.md`, and `tech.md`, plus one pointer line per other steering file; target 150 lines (the two inlined files alone are about 110). Tool adapters carry only what `AGENTS.md` does not: other `always` steering, `fileMatch`, and `manual` files, in the tool's own format (`.claude/rules/` with `paths:`, `.cursor/rules/` globs, `.github/instructions/` `applyTo`, `.kiro/steering/` inclusion). The PreToolUse steering injection is removed; Claude Code's path-scoped rules replace it.

**Commands.** `.claude/commands/sdd/` stays; `/sdd:*` names are a contract. Commands with side effects (`task`, `handoff`, `bug`, `render`) set `disable-model-invocation: true`.

Applies to: the template and every project initialized from 2.1.0. Does not apply to: v2.0 projects until they run `sdd upgrade` with `--answers`.

## Consequences

- Positive: fixes reach derived projects as a merge, not a copy; edited files are never silently overwritten; Codex and Copilot sessions load less; the gate works in multi-repository cloud sessions.
- Negative or cost: upgrade needs a local checkout of the template with tags; init writes two more records; the adapter fixtures change.
- Operational: maintainers tag every release, since upgrade rebuilds the base from the recorded commit.

## Risks

| Risk | Impact | Mitigation or verification |
|---|---|---|
| The recorded commit is missing from the checkout | no base, no merge | `upgrade` stops and names `git fetch --tags`; `--base-ref` overrides |
| Init output differs between OS line endings | false conflicts | both renders and the project file are normalized to LF before `merge-file` |
| A model invokes a side-effect command on its own | unintended writes | `disable-model-invocation: true` |

## Revisit when

- A second maintainer or a third derived project exists: extract `@vxerys/sdd`.
- Claude Code stops honoring `.claude/commands/` or `paths:` rules.
