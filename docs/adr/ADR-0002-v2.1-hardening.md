# ADR-0002: v2.1 hardening

## Context

v2.0.0 shipped on 2026-10-15 (ADR-0001). A fresh-eyes audit and a benchmark against spec-kit, OpenSpec, BMAD, Kiro and Anthropic guidance found, before any real use:

- Bugs that hit the first derived project: the copied CI validates `examples/` (deleted by init) and re-runs `init` (fails without `--force`); hooks import `yaml` before their try/catch so a missing `node_modules` silently disables the guard; PostToolUse/Stop output never reaches the model; the repo walk ignores `.gitignore` (parses `ios/Pods/**`); the Supabase preset writes `supabase db reset` while `rules.md` forbids `reset`; example personas survive `init` and render into AGENTS.md; secret patterns miss `key.properties`, `GoogleService-Info.plist`, `*.p12`, `*.p8`, `*.mobileprovision`.
- Trust gaps: an EV block passes with `command: echo pass`, `output: ok`, a `commit` that does not exist; status transitions are not enforced; an open assumption without `feature:` bypasses the gate; a malformed heading hides a task; the guard covers only Edit/Write and leaves `sdd.config.json`, `checks.mjs` and `.claude/settings.json` editable; nothing defines who moves a task to `done`, and EV commits are recorded before the code is committed.
- Structure: tooling is copied into every derived project, so fixes never propagate, and Flutter/Kotlin repos carry Node only for docs tooling.
- The owner now runs several cloud agents (builder every 3 h, PR review per PR, docs-drift weekly) plus manual sessions on the same repos, and cloud sessions that attach more than one repo load no hooks.

## Decision

**Packaging.** Tooling moves to an npm package `@vxerys/sdd` (own repo). The template keeps docs, config, `.claude/`, CI. Projects call `npx @vxerys/sdd <cmd>`; hooks call the same. `sdd.config.json` records `templateVersion`; `sdd upgrade` refreshes managed paths (templates, commands, settings, CI, protocol docs; list overridable in `sdd.config.json.managed`) with `git merge-file` 3-way merge and never touches steering content, specs, product docs, ADRs, handoff, assumptions.

**Trusted evidence and lifecycle.** Order is fixed: implement → commit → `sdd verify T-xxx` (runs the `tech.md` commands, refuses a dirty tree, writes EV blocks with real output, exit code, `git rev-parse HEAD`, `captured: true`) → `/sdd:review` runs a clean-context verifier subagent that compares diff and EV against the task's ACs and, on pass, sets `reviewed_by: verifier@<hash>` and `status: done`; a human may set `reviewed_by: <name>`. Validator: `done` requires `reviewed_by`, every EV `captured`, `commit` present in `git log`, `command` present in `tech.md`; transitions follow the state machine; a `done` task's evidence must cover the ACs of its own FRs; malformed task/FR/EV headings are errors; an assumption without `feature:` is an error.

**Guard hardening.** Guard also matches Bash (writes or `sed -i`/redirects into generated, frozen, secret paths; reads of `.env*`), NotebookEdit, and protects `sdd.config.json`, `.claude/settings.json`, `.claude/commands/`, and the package's own check code. Hooks fail closed on import errors for PreToolUse (deny with reason) and fail open elsewhere. Stop blocks only when `tasks.md` changed this session and (validate has errors or the handoff is untouched), at most two consecutive blocks, then releases with a warning. Hook output uses the JSON forms so it reaches the model.

**Multi-agent locks** (`collaboration: single | multi`, override `--mode`). A claim is: `claimed_by` (session URL or routine name) and `claimed_at` on the task block, plus a pushed `feature/T-xxx` branch with a draft PR to `git.baseBranch`. Open PRs to the base branch are the lock source when `gh`/`GH_TOKEN` is available, otherwise the claim fields with staleness `limits.claimHours` (default 6). One `in_progress` task per run; a run may take a task only when its `depends_on` are `done`, no open claim exists, and its `scope` does not intersect another claimed task's `scope`; when unsure, skip. `multi` makes stale claims, stale handoff and claim-less `in_progress` errors; `single` makes them warnings. `/sdd:worktree T-xxx` is optional, local only.

**Hookless parity.** `sdd brief`, `sdd guard --check` (fails when `git diff` touches generated, frozen or secret paths), and `sdd validate` give cloud sessions the same gates; routine prompts call them explicitly. Tool hook configs are rendered for Cursor, Codex, Gemini, Copilot and Kiro through per-tool shims that normalise input; each is marked verified only after a real run.

**Context size.** AGENTS.md is rendered thin: identity, read-first, `rules.md`, the `tech.md` commands table, pointers to the other steering files, and for tools without hooks the line "run `npx @vxerys/sdd brief` first" (target ≤120 lines).

**Spec quality.** Validator lint: every FR has ≥1 AC; an AC is Given/When/Then, EARS, or contains a measurable value; a banned-word list (fast, user-friendly, robust, appropriate, easy, simple, …) warns; `approved` requires zero lint errors. `/sdd:analyze` (semantic, read-only) and `/sdd:clarify` (≤5 questions, answers written as `A-xxx`) are commands. `/sdd:feature <slug>` creates a feature folder with the next id.

**Also.** `examples/flutter-supabase` (lite, docs-only) joins `examples/todo-api` in the package repo; the Flutter preset adds `*.g.dart`, `*.freezed.dart` to `generated` and the Supabase preset's change check becomes `supabase db diff`; `.gitignore` gets per-preset entries; the walk honours `.gitignore`.

Deferred until evidence of need: AC→test stubs, GitHub Issues sync, property tests.

## Consequences

- Derived projects get fixes by bumping one version; a second repo (`VXerys/sdd`) to maintain. Until the owner has an npm account, projects depend on the GitHub tag (`"@vxerys/sdd": "github:VXerys/sdd#v2.1.0"`) and `sdd upgrade` resolves template versions from git tags; publishing to npm is a later, non-breaking switch.
- Evidence can no longer be typed by hand for `done`; manual checks (UI, device) are recorded as EV with `captured: false` and need `reviewed_by: <human>`.
- `multi` mode needs `gh` or `GH_TOKEN` in routines for PR-based locks; without it the claim fields still work.

## Execution (2.1.0, one PR per phase)

1. Hardening in place: all bugs above, validator trust rules, guard coverage, hook fail-closed/JSON output, `.gitignore` walk, preset fixes.
2. Package extraction to `@vxerys/sdd`, `sdd upgrade`, `templateVersion`, examples move, CI rewritten for derived repos.
3. Lifecycle: `sdd verify`, verifier subagent, `/sdd:review` done-transition, `/sdd:feature`, `/sdd:clarify`, thin AGENTS.md, Stop blocking.
4. Multi-agent: claims, PR lock source, `collaboration` mode, `sdd brief` / `sdd guard --check`, hook shims for five tools, `/sdd:worktree`.
5. Spec lint, `/sdd:analyze`, `examples/flutter-supabase`, release 2.1.0.

Each phase: `npm test` and `sdd validate --strict` green. Outward actions (new repo, npm publish, push, PR, tag) need explicit owner approval each time.
